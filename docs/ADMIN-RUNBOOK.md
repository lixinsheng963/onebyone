# 管理端运营手册（官方账号 / 学校授权 / 团队权限）

适用版本：`v0.3.0-rc.5` 之后。所有操作都在管理端完成；小程序端只负责登录、发布和接收通知。

## 一、官方账号完整流程

### 角色

- **平台管理员**：创建官方账号、绑定运营者、复核生效、暂停。
- **学校审核人**：只能初审本学校/本组织的官方账号，提交平台复核；不能直接生效。
- **官方账号运营者**：真实微信用户，绑定后以官方身份在小程序发布内容。

### 操作顺序

1. **先让运营者登录一次小程序**
   - 运营者用自己的微信登录小程序，完成邀请码认证；
   - 这样系统里才会出现这个用户，平台管理员才能在“用户治理”里找到。

2. **创建官方账号**
   - 管理端 → 官方账号 → 新建官方账号；
   - 填组织名称、组织标识（例如 `org_library`）、授权范围、授权有效期；
   - 创建后状态为“待学校审核”。

3. **绑定运营者（必须）**
   - 在官方账号卡片点“绑定运营者”；
   - 从用户列表选择真实运营者，确认；
   - 绑定的用户当前必须是 active，未封禁/未注销/未禁言；
   - 一个用户只能绑定一个官方账号；
   - 生效前绑定：先记录关系，审核通过后才获得官方身份；
   - 生效后换绑：新运营者立即获得官方身份，旧运营者自动降级回原角色。

4. **上传学校授权材料**
   - 官方账号卡片 → 上传授权文件；
   - 支持 PDF/JPG/PNG，最大 8MB；
   - 文件存私有目录，后台登录后才能查看；
   - 建议：盖章授权函、有效期、运营者、发布范围、责任声明。

5. **学校审核人初审**
   - 学校审核人登录管理端；
   - 单校版中可看到本校全部官方账号，但必须回避自己所属组织；
   - 点“提交平台复核”；
   - 不能点“通过并生效”；
   - 不能审核自己所在组织（同 `orgId` 会被拒绝）。

6. **平台管理员复核**
   - 平台管理员看到“待平台复核”；
   - 点“通过并生效”；
   - 生效后运营者在小程序的用户角色变为 L4 官方身份；
   - 到期自动过期并降级。

7. **暂停 / 换绑 / 过期**
   - 平台管理员可以把 active 账号暂停；
   - 暂停/过期后运营者官方标识自动移除，恢复原角色；
   - 换绑时旧运营者自动降级，新运营者按账号状态生效；
   - 所有操作写入审计日志。

### 自测清单

| 步骤 | 预期 |
|---|---|
| 创建官方账号 | 状态“待学校审核”，运营者显示“未绑定（占位）” |
| 绑定运营者 | 卡片显示运营者昵称；用户治理中该用户仍为原角色（未生效） |
| 上传 PDF | 卡片显示文件名，可“查看授权文件” |
| 同组织学校审核人提交 | 403，提示不能审核本人所在组织 |
| 其他组织学校审核人提交 | 状态“待平台复核” |
| 学校审核人点生效 | 403，提示只能提交平台复核 |
| 平台管理员通过 | 状态“已生效”，运营者 L4/官方 |
| 暂停 | 状态“已暂停”，运营者降级回原角色 |
| 换绑 | 新运营者生效，旧运营者降级 |
| 有效期改为过去并刷新 | 状态“授权已过期”，运营者降级 |

> 当前账号 `oa_library` / `oa_club` 是历史数据；正式使用前按上面流程重新绑定真实运营者。

## 二、学校授权材料与学校审核人流程

### 学校审核人怎么建

1. 平台管理员 → 团队权限 → 新建操作员；
2. 角色选“学校审核人”；
3. 填姓名、邮箱、初始密码、学校 ID、组织 ID；
4. 创建后把账号密码线下交给本人；
5. 本人登录管理端，只能看到概览、官方账号、通知；
6. 离职/换岗：团队权限 → 吊销；旧 token 立即失效。

### 学校审核人的边界

- 只能初审官方账号，不能审核普通帖子；
- 不能看举报、排名、邀请码、审计、团队；
- 只能上传/查看本组织授权文件；
- 不能直接让官方账号生效；
- 同组织自审会被拒绝，需要另一名学校审核人或平台管理员处理。

### 授权材料要求

系统只校验格式与大小，业务上建议：

- 学校/组织盖章的授权函；
- 明确官方账号运营者；
- 明确发布范围（通知/紧急通知/校徽）；
- 明确授权期限；
- 明确责任与撤回方式；
- PDF 优先，扫描件 JPG/PNG 也可。

不要用聊天截图、个人保证书替代学校正式授权。

### 自测清单

1. 平台创建学校审核人；
2. 学校审核人登录，确认看不到审核队列/举报/排名/团队；
3. 上传本组织授权文件；
4. 提交平台复核；
5. 平台通过；
6. 吊销学校审核人，确认旧 token 401、重新登录失败。

## 三、团队权限流程

| 角色 | 可见栏目 | 能力 |
|---|---|---|
| 平台管理员 | 全部 | 创建/吊销操作员、官方账号复核、邀请码、排名、审计、用户治理 |
| 内容审核员 | 概览、审核队列、举报、用户（只读） | 内容单人终审、举报处理；不能改排名/邀请码/团队 |
| 学校审核人 | 概览、官方账号、通知 | 学校初审、授权材料；不能审核普通内容 |

### 操作

1. 团队权限 → 新建操作员；
2. 选角色，填姓名/邮箱/初始密码；
3. 学校审核人必须填学校 ID、组织 ID；
4. 创建后线下交付；
5. 吊销后旧会话立即失效；
6. 所有创建/吊销都有审计日志。

### 建议

- 平台管理员只保留 1～2 个；
- 内容审核员按班次建，不共用；
- 学校审核人按学校/组织建；
- 离职立即吊销，不要只改密码；
- 不要给学校审核人平台管理员角色。

## 四、邮箱告警

已配置的目标收件人：`2576264825@qq.com`。

服务器需要提供 QQ 邮箱 SMTP 授权码（不是登录密码；本地已实测发信成功，授权码只写入生产环境变量，不要提交仓库）：

```env
ALERT_EMAIL_TO=2576264825@qq.com
ALERT_EMAIL_FROM=你的发件QQ邮箱
ALERT_SMTP_URL=smtps://smtp.qq.com:465
ALERT_SMTP_USER=你的发件QQ邮箱
ALERT_SMTP_PASS=QQ邮箱SMTP授权码
ALERT_STATE_FILE=/var/lib/campus/health-alert.state
```

安装定时器：

```bash
sudo cp deploy/systemd/campus-healthcheck.service /etc/systemd/system/
sudo cp deploy/systemd/campus-healthcheck.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now campus-healthcheck.timer
```

手动验证（不会真的发信）：

```bash
ALERT_DRY_RUN=1 deploy/scripts/send-alert-email.sh "测试" "这是一封测试邮件"
```

真正发信需要 SMTP 授权码；没有授权码时只能做 dry-run，不能声称邮件已送达。
