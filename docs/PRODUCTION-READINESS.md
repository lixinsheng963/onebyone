# 生产上线清单 / Production Readiness

> 版本：`v0.2.0-preproduction`  
> 更新：2026-11-16  
> 目标：单校版正式部署上线。四份源文档仍是产品/业务/设计/排版的权威依据；本文件只记录工程状态、上线阻断项和验收标准。

## 1. 当前结论

单校版核心业务闭环已经跑通：小程序登录/邀请码、信息流、发布、评论/回复、点赞/收藏、通知、举报、我的页面，管理端审核/官方账号/通知/举报/热度/邀请码/审计，MySQL 规范化持久化、Redis 限流、AI 文本初筛和举报复核、自动化 e2e 与安全 smoke 均已落地。

**当前仍不是可直接对外发布的版本。** 以下 P0 项属于“简化实现”或“尚未接入”，是正式上线的阻断项。

## 2. 上线阻断项（P0）

### P0-01 官方账号授权与审核链

- 现状：管理端可一键修改官方账号状态；`official_accounts.authorization_file_key` 字段存在，但没有授权文件上传、学校审核人初审、平台复核、到期降级/撤销的完整流程。
- 目标：
  - 管理端可创建/编辑官方账号，填写组织名称、授权范围（校徽/通知/紧急通知）、有效期；
  - 上传授权文件（PDF/JPG/PNG，大小与 MIME 校验，COS 或本地私有存储，后台可下载/预览）；
  - 状态链 `pending_school → pending_platform → active`，学校审核人与平台管理员分别操作；
  - 支持 `suspended`/`expired`，到期自动降级，历史内容保留但不再显示官方标识；
  - 学校审核人不能审核自己所在社团；所有操作写审计日志。
- 验收：三阶段 e2e；越权/回避/过期/撤销测试；授权文件不可匿名访问。

### P0-02 学校审核人与后台 RBAC

- 现状：管理端只有 env 配置的平台管理员；`school_reviewers` 表为空，未接业务；没有按角色渲染/服务端校验。
- 目标：
  - `admin_users.role` 支持 `platform_admin` / `content_reviewer` / `school_reviewer`；
  - 学校审核人可登录后台，只访问官方账号/通知审核，不看匿名身份、不封普通用户；
  - 支持指定/更换/备班/撤销，旧账号立即失效，操作留审计；
  - 服务端必须再次校验，不能只靠前端隐藏。
- 验收：角色矩阵测试；学校审核人访问审核队列/举报/用户数据返回 403；撤换后旧 session 失效。

### P0-03 账号状态与治理

- 现状：`users.status` 字段存在，但没有禁言、封禁、过期状态，也没有管理端用户管理页；封禁用户仍可能发布/评论。
- 目标：
  - 正常/禁言/封禁/过期；封禁用户不能发布、评论、点赞、收藏、举报；
  - 管理端可按用户/公开 ID 查询、禁言、封禁、解封，必须写理由；
  - 所有操作写审计；用户收到站内通知。
- 验收：状态机测试；封禁后所有写接口 403；解封恢复；越权测试。

### P0-04 账号注销与数据删除

- 现状：设置页“注销账号”只弹“已记录注销申请”，不执行真实删除，见 `apps/miniprogram/pages/settings/index.js`。
- 目标：
  - `DELETE /api/v1/me` 二次确认后注销；
  - 删除/匿名化认证信息、session、个人资料；内容按社区公约/法律要求保留或匿名化；
  - 备份/异步清理有记录；注销后 token 立即失效。
- 验收：注销后 `/me` 401、旧 token 失效、数据库无认证数据；内容处理符合约定。

### P0-05 申诉闭环

- 现状：`POST /api/v1/appeals` 只返回“已提交”，不落库；管理端没有申诉列表/复核页。
- 目标：
  - 新增 `appeals` 表与状态机（pending/reviewing/upheld/rejected）；
  - 申诉必须由未参与原审核的人复核；
  - 管理端可查看原审核记录、理由、证据，改判/维持，通知用户；
  - SLA/超时提示。
- 验收：提交→管理端处理→通知→用户看到结果；原审核人不能复核自己的 case。

### P0-06 P0/P1 双人复核

- 现状：一个管理员即可终审。
- 目标：P0/P1 审核必须两个不同管理员确认；记录两次决策、时间、理由；同一人不能重复确认；紧急情况有平台管理员升级路径并留审计。
- 验收：单人通过被拒绝；双人通过生效；重复同一人 409/400。

### P0-07 图片内容安全

- 现状：图片只做上传/压缩/人工审核，未接 `mediaCheckAsync`/OCR；含图内容强制人工。
- 目标：
  - 接入微信 `mediaCheckAsync`（配置 `WX_APPID/WX_SECRET` 时）或明确的可替换内容安全适配器；
  - 异步结果落库，失败/超时转人工；
  - 不允许图片内容绕过人工审核自动发布。
- 验收：正常图/违规图/超时三条路径；审核状态可追踪；不阻塞发布主流程。

### P0-08 生产微信登录、HTTPS 与部署

- 现状：本地 `ALLOW_DEMO_LOGIN=true`；真实 `code2Session` 代码已有但未生产验证；无域名/HTTPS/ICP/小程序备案；一键脚本未在真实服务器执行。
- 目标：
  - `NODE_ENV=production`、`ALLOW_DEMO_LOGIN=false`、真实 `WX_APPID/WX_SECRET`；
  - 备案域名 + HTTPS + 微信 request 合法域名；
  - Nginx TLS、CORS 白名单、TRUST_PROXY、PUBLIC_BASE_URL；
  - 阿里云/腾讯云实际部署，systemd/健康检查/日志/备份。
- 验收：真机微信登录成功；HTTPS 证书有效；管理端仅 HTTPS；重启后数据不丢。

### P0-09 并发与瞬时压力

- 现状：有功能 e2e 和安全 smoke，但没有正式并发/瞬时压力脚本与指标。
- 目标：
  - 增加压测脚本（登录、feed、发布、评论、邀请码兑换、管理端轮询）；
  - 覆盖瞬时并发（如 100/300/500 并发）与持续 1-5 分钟；
  - 记录 p50/p95/p99、错误率、DB 连接池、内存、Redis；无 5xx/崩溃/数据错乱；
  - 验证限流与防重复提交不会误伤正常用户。
- 验收：压测报告 + 可重复命令；瓶颈有结论和修复。

### P0-10 备份、监控与安全运维

- MySQL 每日备份与恢复演练；COS/本地图片备份；Redis 可不持久化但要有降级。
- 监控：健康检查、5xx、429、登录失败、审核队列积压、磁盘、DB 连接数。
- 生产密钥轮换；管理后台 VPN/IP 白名单；WAF/CDN 评估。

## 3. 外部依赖/需要准备的材料

正式部署前需要确认：

- 已备案域名、HTTPS 证书、微信小程序合法域名；
- 小程序正式 AppID/Secret（测试号不能上线）；
- 阿里云服务器 SSH 访问方式（或由你在服务器执行脚本）；
- COS 桶、子账号密钥、CDN 域名（可选）；
- DeepSeek API Key（可选，失败自动回退规则审核）；
- 学校授权文件与学校审核人书面指定材料；
- 管理员正式密码/TOTP、邀请码策略。
